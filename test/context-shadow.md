# 上下文预算候选

这是默认关闭的实验能力：计算按预算选择的候选输入并记录诊断。普通 CLI/Harness 仍使用既有历史投影和压缩；只有评测包装器显式启用时才应用候选。

## 候选选择

可信调用方以正预算开启影子计算。系统消息和当前完整用户轮必须保留；旧历史以完整用户轮为单位加入，不能拆开工具调用与结果。

选择顺序为：显式用户来源约束 → 成功回读证据所在轮 → 从近到远的其他历史。显式约束保留来源所在轮至当前轮的连续后缀。预算不足如实报告，不通过裁半轮满足预算。

`WithRequiredHistorySources` 最多接受16个来源 ID，只能把完整、未中断的用户消息作为约束；助手答案、摘要、工具结果及失效 ID 记为未解决。当前没有 CLI pin 命令、自动约束提取或跨进程持久 pin 配置。

## 来源与回读

Harness 在影子开启时额外读取来源快照；角色、正文和工具元数据的完整序列匹配后，按位置绑定实际消息对象，不用相同正文猜来源。

`source_status` 区分 matched、mismatch、unavailable、unsupported 和 not_observed。matched 证明两次投影一致，不证明两次读取属于同一事务；额外快照也有读取成本。

只有本轮成功的 `read_history_source` 回读且来源仍能映射到历史消息时，才进入回读证据集合。搜索预览、浏览预览、失败回读和中断来源不自动升格为证据。回读存在也不证明模型理解了内容。

## 诊断与回退

报告包括来源映射、必留/保留标记、预算状态、未解决约束与回读、被省略的证据轮，以及原始/候选输入估算。不包含消息正文或工具原始参数。

评测应用前校验来源匹配、当前轮、完整轮边界、消息计数与索引。未知工具定义、来源不匹配、未解决约束、非法候选或预算不足等情况回退完整输入，并记录原因。SDK 建流重试复用同一候选，下次逻辑调用重新计算。

使用方式见 [上下文基线](contextbaseline/README.md)。已有小样本 A/B 显示可以发生实际裁剪，但长度约束表现不稳定，尚未证明稳定质量或整体任务成本收益。
