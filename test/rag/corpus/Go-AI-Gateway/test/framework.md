# F-4 框架验收

固定场景：用户请求发布验收记录，模型提出工具调用，经两步确认后执行，工具返回回执，模型续答。发布工具为受控夹具，不访问真实业务系统；它验证框架连接，不代表项目已经选定产品用途。

```text
用户任务 -> NewConfigured -> 模型 HTTP 替身 -> 工具 guard -> 提案
用户决定 -> 原子领取 -> 执行状态 -> 原工具 -> 结果日志 -> 模型续答
新 Harness -> 读取执行状态/历史 -> 新轮次（不重放原工具）
```

| 分支 | 工具进入次数 | 持久化状态 | 验收重点 |
|---|---|---|---|
| 成功 | 1 | succeeded | 原参数准确、回执进入续答和重新读取的历史 |
| 拒绝 | 0 | rejected | 续答说明拒绝，重复确认不执行 |
| 失败 | 1 | unknown | 错误进入续答，不能根据错误断言副作用未发生 |
| 取消 | 1 | unknown | 用真实运行 ID 取消，工具退出、运行名额释放；重新进入后 Repair 闭合历史 |

所有分支重新构造 Harness，查询原执行记录，尝试旧确认码，再运行新轮次；工具计数不能增加，事件日志必须通过 ValidateLog。取消时结果写入可能因 context 取消失败，不能要求回执一定存在；执行状态使用独立收尾时限持久化。

替换验收分别连接两个独立 HTTP 模型替身、注入 publish/archive 两个工具；每个都走审批与续答，原模型零请求。证明既有配置入口可扩展，不代表验证了不同厂商协议或模型推理质量。

在 WSL 中运行：

```bash
cd "/mnt/e/agent study/Go-AI-Gateway"
scripts/test-fast.sh -run Framework
scripts/test-fast.sh
```

定向预计 2 个顶层用例（第一个包含四个分支），全量预计 131 个；以实际输出为准，跳过不能充当验收通过。假模型与真实 Redis，无真实模型费用。失败时脚本输出详细日志。

与 F-1～F-3 既有验收合并判断框架完成：WS/RPC 跨入口控制、子日志隔离、持久化失败屏障与实际 MCP stdio 已有各自回归，本文件不复制这些用例。真实模型任务成功率、压力、Redis 容灾、多进程互斥和子任务独立恢复不在此保证范围。
