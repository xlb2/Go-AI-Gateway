# 检索架构与技术取舍

当前实现由不可变原文版本、字符分段、关键词定位、远端 embedding、向量召回和 RRF 融合组成。它是小规模资料检索的实验基线，未自动装入 CLI 或 Web 对话。

## 1. 结构

```text
原文版本 → 800/100字符分段 → 显式 embedding → MySQL向量表
    ↓                                           ↓
关键词字面定位                              余弦相似度
    └──────────────── source级RRF ───────────────┘
                              ↓
                   来源 / 版本 / 原文坐标
                              ↓
                    read_source → 证据片段
```

检索只返回候选与位置，读取结果由事件投影形成证据；不把模型自己写出的引用当作已读取证明。

## 2. Embedding 适配

选择兼容 `/embeddings` 的远端 API，通过 `Embedder` 隔离端点与模型。它避免部署本地推理运行时，但带来网络、密钥、用量与服务限制；本地模型可通过接口另行替换。

配置来自环境变量。模型与维度记录在索引规则中，查询先按模型寻找索引，再核对实际维度，避免新进程尚未学习维度时误判索引缺失。完整接口见 [向量契约](../knowledge/vector.md)。

未选择本地 ONNX、独立推理容器等方案，是为了控制当前依赖范围；不据此判断它们的通用效果优劣。

## 3. 存储与构建

选择 MySQL BLOB 保存归一化 float32 向量，Go 执行线性余弦扫描，复用原文与分段的存储及归属关系。暂不引入独立向量库或 ANN；代价是检索成本随候选数量增长，当前扫描上限20000，不提供真实规模延迟保证。

文本导入与分段同事务，embedding 网络调用位于事务外。写向量时重新校验当前版本，事务替换该版本向量与索引记录；换模型需重建。导入不会自动联网，不提供后台索引队列。

## 4. 融合与分段

关键词计数与余弦分数量纲不同，因此选择只使用排名的 RRF：`Σ 1/(60+rank)`。常数60固定，尚未调优；归一化加权等方案可作为未来对照。

融合按 source 粒度，与现有题集的标准来源口径一致；chunk坐标只用于定位。RRF 可能奖励两路共识，挤掉仅单路命中的正确来源，混合并不保证总优于单路。关键词逐词查库及向量候选截断也会影响成本与召回，详见 [混合契约](../knowledge/hybrid.md)。

保留 `rune-window-800-overlap-100-v1`，让三路比较共享分段条件。Markdown 语义分段、不同窗口大小或重排器需要独立评测，并更新规则版本，避免同时改变多个变量后误判收益。

## 5. 评测与边界

[评测说明](README.md) 固定语料校验、开发/保留集划分和 source recall@5/recall@1。向量评分先按每来源最好chunk聚合；只取top-5 chunk再去重会系统性压低来源召回，不能沿用该口径。

当前保留集冻结，开发集已用于迭代。未提供答案生成质量、拒答机制、生产P99、真实规模压测或长期索引运维保证。选择 ANN、换分段或增加重排，应由规模与失败样本证据驱动。
