# Harness 装配与恢复测试

通过受控发布工具验证配置入口、模型调用、策略检查、审批、执行、日志与续答的完整连接。夹具不访问真实业务系统。

```text
任务 → NewConfigured → 假模型 → 工具策略 → 待审批提案
批准/拒绝 → 原子领取 → 执行状态 → 工具结果 → 模型续答
重新构造 Harness → 读取状态与历史 → 新轮次
```

| 分支 | 工具进入次数 | 执行状态 | 检查内容 |
|---|---|---|---|
| 成功 | 1 | succeeded | 原参数、回执与重新读取的历史一致 |
| 拒绝 | 0 | rejected | 续答说明拒绝，旧确认码不执行 |
| 失败 | 1 | unknown | 错误进入续答，外部副作用保持未知 |
| 取消 | 1 | unknown | 真实运行ID取消、释放运行名额，Repair闭合开放历史 |

重新构造 Harness 后再次查询执行记录、使用旧确认码并发起新轮次，检查工具未被重复派发、日志满足 `ValidateLog`。取消可能中断结果写入，执行状态使用独立收尾时限保存。

替换装配测试注入两个独立 HTTP 模型替身及不同工具，验证依赖替换不会串用原实例。

```bash
bash scripts/test-fast.sh -run Framework
```

需要 Redis，不调用真实模型。该测试不评估模型质量、跨进程互斥、外部副作用恰好一次或 Redis 容灾。
